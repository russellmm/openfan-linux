## Verification standard now required (the lesson)

1. **Geometry proves nothing.** A transparent window measures identically to a working one. Every Release build today
   was "verified" with xwininfo size only, which is why this reached the user.
2. **Xvfb cannot expose presentation bugs** — no GLX there, Avalonia always renders in software. Lab screenshots prove
   startup/layout/labels, never that GL presents on hardware.
3. **Never launch-and-kill repeatedly on the user's live desktop.** Use `hd` on `:99`; touch `:0` once at a time, only
   when the user has agreed, and let *them* initiate it.
4. Capture pixels with `hd shot` on the lab display. On the real session my capture attempts all failed
   (`import -window root`, `xwd`, no `gnome-screenshot`); `import -window <id>` returns black for GL windows — don't
   trust it. `strings` needs `-el` for .NET metadata (UTF-16), otherwise labels appear absent.

## Operational traps (each already cost time)

- `pkill -f <pattern>` **self-kills the shell** if the pattern text appears anywhere in the same command line — use
  bracketed patterns (`openfan[.]dll`) AND keep the literal out of that line, or kill recorded PIDs.
- `kill $!` after `setsid … &` kills the wrapper, not the app (PID off by one). Verify the real PID and check the log
  lacks `OpenFan is already running (lock: /run/user/1000/openfan.lock)`.
- `dotnet test tests/OpenFan.Core.Tests` does **not** rebuild the Avalonia app — build `src/OpenFan.Linux.App` first.
- Repo fs is fuseblk: exec bits unrepresentable, `git config core.fileMode false` is set.
- Single-instance lock `/run/user/1000/openfan.lock` means a stale instance can silently make a test measure the old build.
- Root only via `~/.dsh/skills/grant-root/scripts/root-run.sh`. Approval prompts are disabled — never set
  `sandbox_permissions`. Their live config comes from `~/.config/openfan/active` → `~/Documents/openfan2.json`; never
  edit it while an instance runs.
