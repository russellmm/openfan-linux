# OpenFan Linux v0.4.1 — installed desktop application

This first packaged release installs OpenFan on the Linux system drive, independent of its
development checkout. It includes the accumulated CPU, fan-control and sensor improvements.

## Download and install

Download **openfan_0.4.1_amd64.deb** and **SHA256SUMS** into the same directory:

```sh
sha256sum -c SHA256SUMS
sudo apt install ./openfan_0.4.1_amd64.deb
sudo usermod -aG openfan "$USER"
```

Log out and back in if your group membership changed. Tested on **Ubuntu 26.10, amd64**.
The .NET runtime is bundled; native dependencies are installed by apt. NVIDIA functionality
requires a working NVIDIA driver/NVML. Board PWM permissions and optional DDR5/HSMP setup
remain hardware-specific; see the [installation guide](https://github.com/russellmm/openfan-linux/blob/v0.4.1/docs/installation.md).

The app installs under `/opt/openfan/app`, with `/usr/bin/openfan` as its stable launcher and
the privileged helper under `/usr/lib/openfan`. Existing profiles and calibration are preserved.
The helper is managed by systemd; an older manually installed full service override must be
reviewed/migrated as explained in the guide. Close the app before upgrading its package.

## Included improvements

- NVIDIA 0% curve targets use automatic GPU fan-stop; positive targets resume manual control.
  Nonzero hardware floors, including the RTX PRO 6000's 30%, remain enforced. Firmware can run
  its fan when thermally required even with a zero curve target.
- Real NVIDIA fan RPM and calibration, synchronized slider/Point %, floor-aware sweeps, and
  per-fan points/avoid flags saved in configuration JSON. Cancel preserves existing calibration.
- Compact sensor tables with responsive name editing and saved hide/collapse choices that pause
  optional polling while retaining readings needed by active controls and overlays.
- DDR5 SPD5118 temperatures and read-only thresholds, NVMe activity and SMART health, and clearer
  drive labels. Unverified internal temperature-probe locations remain explicitly unmapped.
- Live physical-core CPU frequency tables with all-core and individual-core caps.
- Package-managed app/helper, desktop icon and menu entry, migration of legacy helper boot links,
  and autostart that preserves custom GPU-routing launchers.
- Tmds.DBus.Protocol updated to patched **0.21.3** for
  [GHSA-xrw6-gwf8-vvr9](https://github.com/advisories/GHSA-xrw6-gwf8-vvr9).
  Sleep/resume monitoring also matches the logind sender and object path explicitly.

## Known limitations

- CPU frequency caps are live settings; frequency-cap reboot persistence is still planned.
  Existing CPU PPT power-limit persistence is separate.
- **Hardware maximum** used in Power saver can leave a 4 GHz request after changing power
  profiles. Switch to Balanced/Performance first, then apply Hardware maximum. The underlying
  fix remains pending; see [the investigation](https://github.com/russellmm/openfan-linux/blob/v0.4.1/CPU-BOOST-CLAMP-README.md).
- Sensor coverage depends on kernel drivers and hardware. Internal NVMe probe locations and
  unknown board voltage channels are not assigned guessed physical labels.

Validation includes **281 automated tests**, isolated desktop/autostart checks, package
dependency and ownership checks, and installation on the target workstation. Build identification
inside the package records the exact source commit; SHA256SUMS verifies the downloaded installer.
