# OpenFan Linux v0.4.6

November 14, 2026

Sensors now includes a dedicated **BMC** group, with CPU/LAN/PCIe temperatures,
slot-labeled **DIMMA1_Temp through DIMMH1_Temp**, fan RPM and manual duty targets.
The tested WRX90 exposes 45 rows: 22 temperature records, 16 fan records and seven duty
targets. Unavailable readings remain missing; real zero RPM and threshold-alarm values
are retained. New BMC temperatures support the existing unchecked Use in curves option.
Existing BMC control/tach identities and fan-control behavior are preserved.

All **eight direct DIMM temperature sensors** are also readable on this workstation.
The old startup script checked only 0x50/0x52 on each memory bus, missing the four hubs at
0x51/0x53. The updated machine-specific script binds all four validated addresses on each
verified WRX90 memory controller, skips existing devices and is installed for future boots.
This startup setup remains separate from the app package; see [setup notes](../../packaging/dram-temps/README.md).
The original four sensor identities, aliases, curve choices and calibration are retained.
Physical slot letters for direct SPD addresses remain unmapped. BMC DIMM values differ
from direct SPD readings and are kept separate rather than substituted or merged.

Update app and helper together using `openfan_0.4.6_amd64.deb` from the
[v0.4.6 release](https://github.com/russellmm/openfan-linux/releases/tag/v0.4.6).
Save open edits and exit OpenFan before upgrading. Existing profiles and fan curves are preserved.
No BMC temperature sources, alarm thresholds or firmware settings are changed.

**347 automated tests pass**, covering all eight BMC DIMM slots through the helper,
SDR status/identity parsing, missing values, dedicated grouping, curve source selection,
and canonical BMC tach demand with hidden groups. Hardware checks validated all eight
direct kernel sensor readings and an idempotent restart of the updated startup service.
