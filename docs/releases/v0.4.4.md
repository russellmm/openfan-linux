# OpenFan Linux v0.4.4

November 14, 2026

BMC fan RPM readings no longer disappear when a fan crosses a firmware alarm threshold.
OpenFan previously required an `ok` sensor status and discarded real readings marked
with a threshold alarm. Live CHA_FAN2 at 20% reported **360 RPM** with status `lcr`
while the old helper returned no reading. Numeric readings with threshold alarms now
reach the fan cards and calibration table. Disabled, unavailable and nonnumeric readings
remain missing; they are never substituted with zero. Firmware alarm thresholds are unchanged.

Manual calibration now opens at **30%** (or a higher hardware minimum). Automatic stepping
starts from the slider's selected duty, so the initial button reads **Auto step 30–100%**.
Move the slider lower to calibrate lower duties. This default does not add a control floor:
BMC sliders still allow 0–100% requests, and RTX PRO 6000 controls retain their 30% minimum.
The existing BMC rejection of actual 0% commands with OEM 0xD9 remains reported explicitly.

Update app and helper together using `openfan_0.4.4_amd64.deb` from the
[v0.4.4 release](https://github.com/russellmm/openfan-linux/releases/tag/v0.4.4).
Save any open calibration with OK and exit the app before upgrading. Existing calibration
points, curves, profiles and power settings are preserved.

Validation: **325 automated tests pass**, including helper-client delivery of alarmed
RPM readings and preservation of missing telemetry. Live reproduction covered both
CHA_FAN2 and CHA_FAN3; original curves were restored exactly after each test.
