## RTX 5060 Ti zero-target fix

The user reported 0% on an enabled curve with approximately 1,017 RPM, versus 0 RPM when
the curve was disabled. Reproduced on GPU `GPU-551a52fc-c5ce-c335-e0d7-81fc00948a65`, PCI
01:00.0, fan 0: the old helper accepted manual 0, switched NVML policy to manual and settled
at approximately 1,014 RPM / 30% measured duty at 36–38 °C. Restoring default policy returned
0% and 0 RPM. NVML reports a manual range of 30–100 for this board, despite accepting 0.

The NVML backend now sends a zero target through `nvmlDeviceSetDefaultFanSpeed_v2` so firmware
can use its fan-stop mode. Positive targets resume manual speed control. Hardware minimums are
applied first, preserving the PRO 6000's existing 30% floor. Automatic mode can run the fan if
the GPU's thermal rules require it: this is not a guarantee of stopped fans at all temperatures.
The helper still tracks session ownership and restores default on disconnect. Direct/root NVML
use and helper use share the same writer behavior; both app and helper must be updated.

The card shows **0% (auto)** alongside real RPM and has an explanatory tooltip. It suppresses
estimated RPM for automatic zero rather than pretending firmware output is a manual target.
Default-policy failures now update `LastWriteError`, as manual failures already did.

Source changes: `src/OpenFan.Linux.Hw/NvmlFanWriter.cs`, `NvmlBackend.cs`, test internals access
in the hardware project, `src/OpenFan.Linux.App/MainWindow.axaml.cs`, README and
`tests/OpenFan.Core.Tests/NvmlFanWriterTests.cs`.
[NVIDIA API semantics](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceCommands.html).
